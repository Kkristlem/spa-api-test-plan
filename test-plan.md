# Чек-лист / тест-план — mock_api_spa_procurement

## GET /api/catalog/products
- [x] 200, непустой список, у каждого товара есть `alerts` (может быть пустым списком).
- [x] Товар с нулевым остатком — `days_of_stock` возвращается или `null`? Проверено: `null`,
      если средний расход = 0 (деление на 0 обработано на бэкенде).

## GET /api/catalog/products/{product_id}
- [x] Несуществующий `product_id` (например `P999`) → 404 с понятным `detail`.
- [x] Существующий товар → в ответе есть `consumption_by_month` за прошлые месяцы.

## POST /api/planning/purchase-recommendation
- [x] Без `product_id` → 422 (обязательный query-параметр).
- [x] `months` вне диапазона 1–12 (например `months=0` или `months=13`) → 422.
- [x] Несуществующий `product_id` → 404 (не 500 — приятно, что обработано явно).
- [ ] Не проверено: конкурентные запросы на один и тот же товар одновременно — не было
      возможности сэмулировать нагрузку в рамках ручного тестирования.

## GET /api/planning/procurement-plan
- [x] `within_budget=false`, когда сумма по товарам превышает `budget_limit_rub` —
      проверила вручную пересчётом суммы `items[].cost_rub`, сошлось.
- [x] `budget_by_month` и `budget_by_category` в сумме дают `total_cost_rub` (с точностью
      до округления).

## GET /api/planning/price-dynamics/{product_id}
- [x] Товар без истории цен → 404 с сообщением «нет истории для сравнения цен» — сообщение
      осмысленное, не generic 404.

## POST /api/chat
- [x] Пустой `question` (`""`) → 422.
- [x] Вопрос не по теме (например «Который час?») → бэкенд всё равно отвечает текстом
      (мок отвечает по ключевым словам), не падает — это скорее находка, чем баг: в
      реальном продукте стоит решить, что делать с вопросами не по теме.

## Общее
